用 SQL 做数据质量核查：一份能直接抄的检查清单

数据核查听起来很虚，落到 SQL 上其实就六类检查。这份清单在日常开发和测试回归里都能直接用。

黄少荣物联网工程（师范）
2026 年 6 月 20 日 7 分钟阅读 软件测试

六类检查

类型问的问题典型场景
完整性必填的有没有缺手机号、服务时长、评价时间
唯一性该唯一的有没有重复同一人对同一服务重复评价
一致性两处说法是否相同订单状态 vs 服务记录状态
有效性值是否在允许范围时长 0 分钟、评分 6 分
及时性时间线是否合理完成时间早于开始时间
业务规则业务约束是否成立一个志愿者同时段接两单

完整性

-- 必填字段缺失
select count(*) as missing
from service_record
where volunteer_id is null
   or start_time is null
   or duration_minutes is null
   or duration_minutes = 0;

唯一性

-- 同一预约被重复评价
select appointment_id, count(*) as c
from evaluation
group by appointment_id
having c > 1;

一致性：跨表对账

-- 预约已完成，但服务记录不存在（孤儿数据）
select a.id
from appointment a
left join service_record s on s.appointment_id = a.id
where a.status = 'COMPLETED'
  and s.id is null;

-- 两侧状态不一致
select a.id, a.status, s.status
from appointment a
join service_record s on s.appointment_id = a.id
where a.status <> s.status;

一致性检查最好成对写：正查（该有的没有）+ 反查（不该有的有了）。只写一半，漏掉的正好是最难发现的那一半。

有效性 + 及时性

-- 数值越界
select * from service_record
where duration_minutes < 0 or duration_minutes > 480;

-- 时间线倒挂
select * from service_record
where end_time < start_time
   or created_at > start_time;

-- 未来时间（脏数据常见来源：手动改库、时区错）
select * from appointment
where created_at > now();

业务规则

-- 同一志愿者同一时段被安排了两单
select volunteer_id, start_time, count(*) as c
from service_record
group by volunteer_id, start_time
having c > 1;

异常值：IQR 比 3σ 更实用

业务数据很少是正态分布，"均值 ± 3 倍标准差"会把正常的长尾当异常。用四分位距更稳：

with ranked as (
  select duration_minutes as v,
         row_number() over (order by duration_minutes) as rn,
         count(*) over () as n
  from service_record
  where duration_minutes is not null
), q as (
  select
    max(case when rn = floor(n * 0.25) then v end) as q1,
    max(case when rn = floor(n * 0.75) then v end) as q3
  from ranked
)
select r.v
from ranked r, q
where r.v < q.q1 - 1.5 * (q.q3 - q.q1)
   or r.v > q.q3 + 1.5 * (q.q3 - q.q1);

数据量大时，这套 SQL 可以固化成视图或定时任务，每天跑一次，结果写进核查日志表，异常直接推送。

Python 做补充

SQL 擅长规则明确的结构化检查；跨文件、跨格式（Excel + 数据库 + 问卷导出）的核查交给 Python 更省事。我的习惯是：能用一条 SQL 说清的绝不写脚本，因为 SQL 可复用、可 review、可交给别人跑。

报告怎么写

每轮核查输出一张表：检查项、覆盖范围、异常数量、样例 ID、判定。别只写"数据正常"——写清楚"查了什么、查了多少、剩下什么风险"。这句话在实习汇报里救过我一次。
